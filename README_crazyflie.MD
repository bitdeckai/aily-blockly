# RobotSTEM · Crazyflie 开发与启动说明

本文档用于说明如何编译、启动并验证 RobotSTEM 的 Crazyflie 相关功能。

> 这里的“编译”指编译 RobotSTEM 应用。Crazyflie 积木程序由电脑上的 Electron 应用通过 Python/cflib 实时发送控制命令，不会在这里编译成可脱离电脑运行的 Crazyflie 固件，也不会自动刷写固件。

## RobotSTEM 第一阶段

- 本分支将产品标题、首页、AI 显示名称和安装包展示名称统一为 RobotSTEM。新建工程的两个入口、设备切换和 AI 设备索引共享本地 Crazyflie 目录，不再提供 Arduino、ESP32 等通用开发板选择或品牌/芯片筛选。
- 当前仅开放已适配的 Crazyflie；开源小车、机械臂是后续扩展方向，不提供未实现的设备选项。新建、切换以及从云模板创建工程均检查设备支持范围；资源缺失会明确报错，不回退到远端开发板目录。
- 保留账户登录、AI 助手、大模型选择/自定义配置、云空间和现有 Crazyflie 全流程。服务地址、OAuth 协议、已有用户数据目录、默认工程路径、`.abi` 扩展名与 `@aily-project` 包标识不机械改名，不迁移或删除用户数据。
- 本阶段保留共享项目、库管理、编译器和传输基础代码，下一阶段再逐项解耦、裁剪；不是删除所有含有 `aily` 或 `arduino` 的文件。原作者版权、许可证、启动页赞助归属及原服务入口保留。
- 在配置独立更新源前停用原产品更新检查、下载和安装，国内/国际打包脚本也不再指向上游更新源，避免安装包将 RobotSTEM 覆盖为原产品。
- 第一阶段回归：`node --test scripts\test-robotstem-product.cjs`；Crazyflie 回归命令仍见下文。

### 后续清理与关闭回归

- 清除本地设备目录的多余异步包装、无调用的旧索引错误处理，以及新建工程中已注释的通用开发板界面和配套字段、模块；账户、AI、大模型、云端模板和旧工程兼容不变。
- Blockly 11 不在核心命名空间导出各语言生成器，移除相关无效清理分支；实际的 `window.Arduino`、`window.MPY` / `window.MicropPython` 库卸载逻辑保留。
- 蓝牙选择器在注册时保存 WebContents 引用，关闭窗口后不再读取已销毁的 BrowserWindow，避免出现 `TypeError: Object has been destroyed`。
- 关闭与蓝牙选择回归：`node --test scripts\test-electron-ble.cjs scripts\test-window-startup.cjs`。测试不连接设备，也不执行飞行程序。

## 快速开始（Windows）

在仓库根目录打开 PowerShell。依赖已经安装好时，只需运行这一条命令：

```powershell
npm run electron
```

第一次运行时，先安装项目和 Electron 依赖，再启动：

```powershell
npm install
npm install --prefix electron
npm run electron
```

模拟器不需要 Python/cflib。若要连接真机，在首次启动前额外安装 cflib 到应用将调用的 Python 环境：

```powershell
py -3 -m pip install --upgrade cflib
py -3 -c "import cflib; print(cflib.__file__)"
```

保持启动命令对应的终端运行。需要制作 Windows 安装包时，改用 `npm run build`；这不是日常开发启动命令。

如果独立构建已通过，但桌面仍显示旧的模板编译错误，请检查 4200 端口是否仍由先前的开发服务占用。`ng build` 不会重启正在运行的 `ng serve`；应先停止本工程旧的开发服务，再重新启动并刷新桌面窗口，以实际开发服务的编译结果为准，不要仅关闭错误遮罩。

## 2. 环境准备

### 2.1 Node.js 与 npm

建议使用项目当前依赖兼容的 Node 版本（项目内包含 child/node 方案，也可使用系统 Node）。

### 2.2 Python

建议安装 Python 3.10 或以上。Windows 下可先用 `py -3 --version` 确认 Python Launcher 能找到 Python 3。

Electron 会优先使用 `PYTHON` 环境变量，其次尝试 Windows Python Launcher（`py -3`）和 `python`。如果机器上有多个 Python，请确保 cflib 安装在实际被 Electron 选中的那个解释器中。也可以在启动应用前指定解释器：

```powershell
$env:PYTHON = "C:\Path\To\Python\python.exe"
py -3 -m pip install --upgrade cflib
```

### 2.3 Crazyflie Python 依赖

在应用会使用的 Python 环境中安装 cflib：

```powershell
py -3 -m pip install --upgrade cflib
```

如果你使用本地 `crazyflie-lib-python` 源码，在启动应用前设置环境变量（路径指向包含 `cflib` 目录的仓库根目录）：

```powershell
$env:CRAZYFLIE_LIB_PATH = "E:\path\to\crazyflie-lib-python"
npm run electron
```

说明：当前实现优先使用 Python 环境中已安装的 cflib；只有显式设置 CRAZYFLIE_LIB_PATH 时才使用本地源码路径。

### 2.4 Crazyradio 与系统驱动

- 确认 Crazyradio 已连接
- Windows 下确保驱动正常（例如通过 Zadig 安装为 libusb-win32/WinUSB，按你现有环境实践）

## 4. 开发模式启动

### 4.1 仅启动前端（Angular）

```powershell
npm run start
```

默认在 `http://localhost:4200/` 启动页面。此方式只启动前端，不会启动 Electron 主进程；Crazyflie 真机 IPC 功能请使用完整桌面应用。

### 4.2 启动完整桌面应用（推荐 Crazyflie 调试）

```powershell
npm run electron
```

此命令会并行启动：
- Angular dev server
- Electron 主进程（并等待 4200 就绪）

此命令会编译 Angular 开发版、启动本地服务，并在服务就绪后打开 Electron。Crazyflie 的链路测试与流程执行由 Electron 调用 Python/cflib 完成。开发服务保持运行时，修改前端代码会自动重新编译。

Windows 启动时恢复普通窗口的位置、大小或最大化状态，不自动恢复全屏，避免遮住系统任务栏。已有的全屏状态会在下次启动时清除，窗口位置和大小按当前显示器工作区校正，避免底部内容落在任务栏后面。

## 5. 编译与打包

### 5.1 标准打包

```powershell
npm run build
```

流程是先执行 Angular 生产构建，再由 electron-builder 制作桌面安装包。Windows 构建产物写入 `dist/aily-blockly/`。这一步用于分发安装包；本地调试请用 `npm run electron`。

### 5.2 区域/渠道打包

- npm run build:cn
- npm run build:global

### 5.3 macOS 打包

在 Mac 上执行 `npm run build:mac`，构建当前机器的原生架构。原 universal 命令不再提供：原生串口、终端与辅助工具需要匹配架构，改用下面的 CI 分别生成 Intel 与 Apple Silicon 安装包。

### 5.4 三平台一键安装包

统一入口为 `scripts/build-electron.js`，建议通过 npm 执行：

```powershell
npm run build:desktop
npm run package:all -- --flavor cn
```

- `build:desktop` 在当前系统及 CPU 架构上生成原生安装包，输出到 `dist/installers/<平台>-<架构>/<渠道>/`；Windows 为 NSIS `.exe`，Linux 为 `.AppImage` 和 `.deb`，macOS 为 `.dmg` 和 `.zip`。
- `package:all` 使用已存在的 `main.yml` 手动触发入口，只执行独立的三平台安装包流程，不运行旧发布、签名或部署任务。Windows x64、Linux x64、Mac ARM64 与 Mac Intel x64 在各自原生 GitHub runner 上构建；脚本等待成功后下载到 `dist/installers/ci-<运行编号>/`。
- 云端构建前须安装并登录 GitHub CLI（`gh auth login`），提交并推送当前分支；脚本拒绝未提交源码或本地、远端不一致的版本。不会替你提交、推送或发布 Release。可加 `--ref RobotSTEM`，或用 `--dry-run` 查看目标而不运行构建。
- 原 `build`、`build:cn`、`build:global` 保留 `dist/aily-blockly/` 输出，兼容原发布流程；渠道为 `cn` 或 `global`，非法参数明确报错。不能在 Windows 上假装生成 Mac 安装包，跨平台请用 CI。
- 首次配置或 CI 环境先执行 `npm ci --include=dev` 和 `npm ci --prefix electron --include=dev`。Unix 本地构建还需要原生 `7zz`、`rg` 和 `ninja`（Ubuntu：`sudo apt install 7zip ripgrep ninja-build`；Mac：`brew install sevenzip ripgrep ninja`），CI 会安装这些工具。
- Unix 包内准备原生 Node/npm、7-Zip、ripgrep、Ninja、C++ 解析库和 probe-rs，不混入 Windows DLL；Mac 工具的非系统动态库随包复制、重定位并保留许可证，不要求用户安装 Homebrew。下载的 probe-rs 校验官方 SHA256。构建时检查工具可执行；构建后用打包版 Electron 的 Node 模式检查串口/终端模块、设备模板及手势模型/WASM，不启动应用或操作硬件。Python 字节缓存不进入安装包。
- CI 使用 Electron 官方下载源。如果本地镜像报 `EOF`，可运行 `npm --electron_builder_binaries_mirror=https://github.com/electron-userland/electron-builder-binaries/releases/download/ run build:desktop`，用命令行参数覆盖项目 `.npmrc`；不修改系统配置。
- 新 CI 默认不签名、不公证；Windows/macOS 可能显示安全提示。真机功能仍需用户安装 Python 3、`cflib` 和适合系统的 USB 驱动/权限，个人 Python 环境和凭据不会进入安装包。

## 6. Crazyflie 功能验证步骤

建议按以下顺序验证：

1. 启动 Electron：`npm run electron`。
2. 打开或创建使用 Crazyflie 开发板的工程，搭建并保存飞行积木程序。
3. 点击顶部立方体按钮显示/隐藏 3D 模拟区，再点击模拟按钮运行仿真；此模式不会连接或操作真机。
4. 真机运行前，连接 Crazyradio 和 Crazyflie，并先运行链路测试积木确认无线链路正常。
5. 顶部选择“模拟”“真机飞行”或“模拟+真机”，再点击“运行”。默认是模拟，不连接硬件；后两种模式会执行真机指令，须由用户明确选择并启动。
6. 查看应用日志和模拟器状态，确认程序执行结果。右下角成功提示在 5 秒后自动收起；错误提示不自动消失，需点击关闭。运行中的进度与取消操作保持原有行为，提示收起不删除执行日志。

首次测试请先做链路测试，不要直接起飞。真机飞行时请使用安全、空旷的区域并确保电池充足；电机测试积木会驱动电机，使用前应移除螺旋桨。

如果链路测试失败，优先检查：
- Python 是否可执行
- cflib 是否安装
- Crazyradio 驱动与连接状态

### 6.1 三种运行模式

| 模式 | 执行方式 |
| --- | --- |
| 模拟 | 使用展开后的飞行计划计算理想轨迹，不连接或控制真机 |
| 真机飞行 | 将计划交给 Python/cflib 执行，不启动模拟轨迹或自动位置跟随 |
| 模拟+真机 | 同一计划只执行一次；实飞同时回传真机 XYZ 和姿态，更新三维模型及轨迹，不再先完整模拟一遍再起飞 |

同步模式参考本地官方 `examples/step-by-step/sbs_motion_commander.py`、`examples/logging/basiclog.py` 和客户端 `src/cfclient/ui/pose_logger.py` 的连接、运动与日志 API。使用实飞自己的连接，以 50 ms 周期在同一日志包读取 `stateEstimate.x/y/z` 和 `stabilizer.roll/pitch/yaw`，不会再开第二个 Crazyradio 连接抢占链路。

- Crazyflie 编辑器隐藏重复的通用编译/上传按钮，统一使用模式选择旁的“运行”；菜单运行及 F6 也遵循当前选中模式，不绕过默认模拟直接实飞。其他开发板不受影响。
- 首帧把真机估计位置和初始航向对齐当前场景停机点；后续显示相对起点的位移、航向变化及真实横滚/俯仰。飞行坐标 X 前、Y 左、Z 上，三维内部对应 -X、+Z、+Y；HUD 的 X 正方向与“向前”一致。
- cflib 起飞会重置 Kalman 估计器。同步订阅该参数的复位完成通知：首次起飞校准对齐场景起点，避免保留起飞前的地面估计漂移；再次起飞从当前落点建立参考，其他飞行中复位保留当前位置，避免把估计器原点变化画成真实位移。没有收到起飞复位通知时，不会擅自归零后续轨迹。
- HUD 位置统一标为 X / Y / Z，单位 cm；Z 显示相对场景起点的上升量，不叠加虚拟桌面或停机坪高度。地面起飞不会因教室虚拟桌面的约 77 cm 偏置被显示成实际离地高度；虚拟停机坪只是坐标参考，不表示真实飞机位于桌上。“模拟航向”表示模型的机头朝向，用于理解模拟转向和机体方向运动，不是真机偏航。
- 真机位置是估计值，不是精确定位保证。官方 MotionCommander 使用速度指令，误差会累积；定位模块、场地、气流、电量和无线延迟都会影响实际运动。理想模拟与实飞复用指令、距离、速度和坐标约定，但不能保证两条物理轨迹完全重合。
- 同步开始前必须收到有效 XYZ/姿态，缺少日志变量或数据会在解锁前失败。运行中日志超过 1 秒无新样本或出现错误，会停止后续命令并走原有降落清理；界面保持末次机载估计值，不切换成假模拟数据。超过 500 ms 无新数据会标记过期。
- 运行中禁止切换模型或复位三维飞行器。结束后保留末次估计位置、姿态和轨迹；底部“重置视角”右侧的“复位”和顶部“复位模型”仅恢复模型起点、清除画面轨迹，不改变相机、不移动真机，也不能解除固件锁定。不会在结束实飞后自动归零来掩盖定位偏差。
- 通知中的取消按钮通过 stdin 请求执行器结束流程：等待当前阻塞动作结束，跳过后续指令并执行降落清理。它不是紧急停机，也不能保证失联时成功降落；界面会等待进程结束，不提前宣称已停止。超时和窗口退出也会请求取消，执行过的流程不会因解释器回退而被重复发送。
- 上述功能以替身连接、合成遥测、旧工程加载和桌面界面进行离线验证；没有自动起飞，也没有验证真实定位误差、无线延迟或降落效果。

### 6.2 纯坐标测试场景

在三维模拟器的场景下拉框选择“坐标系”。该测试场景只有坐标轴、刻度和网格，不含房间、家具、停机台或导入模型，飞行器中心位于 `(0, 0, 0)`；模拟起飞 0.3 米显示 30 cm，降落与复位回到零高度，没有桌面偏置。

- 固定世界坐标：红 X 向前、绿 Y 向左、蓝 Z 向上，三个正交网格面覆盖各轴 `-3～3 m`，数字刻度单位为米；飞机转向不会带动世界坐标轴旋转。
- 近看显示 10 cm 细网格，保留 1 m 粗线；当细格投影小于 8 个 CSS 像素时自动只显示 1 m 网格，拉近后恢复。HUD 标明当前网格间距，“网格”按钮只隐藏网格，不隐藏固定坐标轴。
- 切换场景只改变画面，不插入积木、不自动起飞，也不改变真机指令。运行中仍禁止切换。可用于模拟及“模拟+真机”的位移对照，不提供物理碰撞或真实定位精度保证。

### 6.3 真机起飞状态

- 顶部运行控制旁常驻显示“真机 · 允许起飞 / 待解锁 / 飞行中 / 禁止起飞 / 未确认”；状态独立于可横向滚动的运行工具栏，窄窗口也不会被滚走。模拟区底部显示原因与恢复提示，隐藏模拟区后仍能看到顶部状态。无线“已连接”仅表示通信正常，不代表固件允许起飞。
- 复用已有持久连接，每 500 ms 只读 `supervisor.info`，不新建无线连接，也不自动解锁、重启或重置真机。旧固件回退到 `sys.canfly`；两者均不存在则显示“未确认”，不伪造可飞状态。旧接口无法给出具体禁止原因。
- 翻倒、碰撞、扩展板故障会明确提示；只有固件报告锁定位时才提示检查机体、确认电机已停并安全断电重启。待解锁不等于故障，仍使用原有执行流程，不绕过固件保护。状态无效、断线或超过 1.5 秒没有新可飞遥测时显示“未确认”；电量和链路质量更新不能续期旧的可飞信息。
- “允许起飞”只是固件当时的判断，不是安全保证；仍需检查姿态、定位模块、场地、电量和周围人员。模型复位与真机恢复是两件不同的事。

## 7. 常见问题

### 7.1 提示 Cannot run Python

原因：Electron 未找到可用 Python 命令。

处理：
- 在终端确认 py 或 python 可执行
- 确认 PATH 中有对应解释器
- 重启应用后重试

### 7.2 提示 Cannot locate crazyflie-lib-python (cflib)

原因：当前 Python 环境没有可用 cflib。

处理：
- 执行 pip install cflib
- 或设置 CRAZYFLIE_LIB_PATH 指向本地 crazyflie-lib-python

### 7.3 链路测试失败但 Python 正常

优先排查：
- Crazyradio 驱动
- USB 连接稳定性
- URI 与地址参数（默认 radio://0/80/2M，E7E7E7E7E7）

请注意，`radio://0/80/2M` 和地址 `E7E7E7E7E7` 是默认连接参数；若你的 Crazyradio/Crazyflie 使用不同配置，请在工程或连接参数中使用对应值。

### 基础积木

- Crazyflie 项目自动提供逻辑、循环、数学、文字、时间和变量六个基础分类，排在飞行器与扩展分类前。新旧项目均在打开时加载，无需重新创建项目或额外安装 Arduino 核心库。
- 从 Crazyflie 分类上方以分隔线区分飞行器专用积木。Crazyflie、Crazyradio、光流定位、测距避障、LED 灯环和蜂鸣器均使用与基础分类相同的单行样式，点击直接打开积木列表，不再展开介绍文字。
- 基础积木复用 Blockly 标准定义与 Python 生成器；时间分类提供可连接数值/计算结果的等待积木，文字分类的打印使用 Crazyflie 日志输出。
- 运行前，基础条件、循环、变量和表达式会展开成逐条飞行指令，模拟与实飞使用同一套展开规则。重复执行的积木会按实际指令顺序高亮。
- 当前基础流程只使用运行前可确定的数值和文字，不支持在条件或计算中读取扩展模块的实时传感器；遇到此类积木会明确报错，不会忽略条件或执行两条分支。无穷循环、超过 10000 步的展开、零步长和无效数值也会在发送飞行指令前报错。

- 回归测试：`node --test scripts/test-crazyflie-basic-blocks.cjs`（需要 Python 3，用于校验实飞指令解析，不连接硬件）。

### 常用运动积木

Crazyflie 新旧项目打开后，常用运动与原 Crazyflie 积木合并在一个“Crazyflie”分类中，积木文字跟随现有中英文切换。专用的等待、文本打印、换行打印不再出现在工具箱，改用基础“时间”和“文字”分类；原积木类型及生成器继续注册，旧工程无需改写即可加载、执行。所有运动数值输入都可连接数学、变量和表达式积木。

连接、自检、起飞、降落置于 Crazyflie 分类顶部，之后是带参数的运动积木。基本飞行与运动积木统一使用蓝色，扩展分类保留各自配色。“自检”会短暂测试电机，不是只读检测，真机执行前请先卸下螺旋桨。刷新基础分类前会先注册运动积木及数值输入，避免旧工程重载时出现无效积木定义。

自检在真机模式及模拟+真机模式下会等待固件确认完成，再高亮和执行下一块积木：先以 100 ms 周期订阅 `health.motorTestCount` 与 `health.motorPass`，取得本轮开始前的计数，再发送 `health.startPropTest=1`；计数增加一次（包含 16 位回绕）才视为结束。`startPropTest` 归零只是固件接收了启动请求，不能代表完成；上一轮的 `motorPass` 也不会让本轮提前结束。此行为依据官方固件的 [health.c](https://github.com/bitcraze/crazyflie-firmware/blob/master/src/modules/src/health.c)，不依赖固定 5 秒延时或新版固件才提供的完成位。

若固件缺少上述参数/日志变量，自检不会启动并明确报错；3 秒没有新状态、20 秒仍未结束、断线、日志异常或取消都会停止后续积木，释放本次日志与回调，不自动重试。固件的电机测试没有在这里提供可确认的中途停止接口，因此取消/超时不代表电机已停，必须观察电机停止后再操作。完成计数只证明测试流程结束，日志中的 `motorPass` 低四位记录各电机结果，是否设置了检测阈值取决于固件参数，不能把“完成”当成整机适航保证。仅模拟模式用约 5 秒展示自检过程（可随模拟速度调整），不读取硬件也不声称是真机结果。无硬件回归：`node --test scripts\test-crazyflie-self-test.cjs`。

基础分类与飞行器专用分类之间有分隔线。Crazyflie 下方的独立 **Crazyradio** 分类提供：
- **检测无线收发器**：检测 USB 无线收发器并在真机日志输出版本，不启动电机。
- **扫描飞行器**：按配置地址扫描所选无线收发器，输出包含该设备编号或序列号的完整 URI；未找到飞行器会明确输出 0 个结果，不伪造链接。使用官方 cflib 的 URI 解析、共享无线驱动和通道扫描接口，支持非 0 编号与序列号，不会悄悄扫描另一设备。放在流程开头、连接之前；扫描失败或取消会释放扫描驱动并终止流程，不会继续连接或起飞。
- **无线收发器参数**：选择无线收发器编号、信道 0–125、速率 250K/1M/2M、10 位十六进制地址，生成官方格式 URI（包括地址）。在连接前设置，只配置本次连接，不修改飞行器固件中的无线参数。

原“连接 URI”积木不再出现在工具箱，但仍保留定义与生成器，旧工程中的积木可以正常加载、执行。检测与连接设置的积木类型保持兼容。仅模拟模式不访问 USB、不扫描真实无线收发器，也不会伪造检测结果。执行纯无线收发器检测/扫描时选择“真机飞行”模式；“模拟+真机”模式仍要求连接飞行器并获取真实位置。

| 积木 | 参数及含义 |
| --- | --- |
| 起飞至指定高度 | 高度（米）、起飞速度（米/秒）；高度相对本次起飞位置，不是绝对世界坐标 |
| 按速度降落 | 降落速度（米/秒） |
| 按方向和速度移动 | 前、后、左、右、上、下；距离（米）、速度（米/秒） |
| 转向 | 左/右；角度（度）、角速度（度/秒） |
| 圆弧/绕圆 | 左/右；半径（米）、角度（度）、速度（米/秒）；360 度为整圆 |
| 三轴移动 | 当前机体坐标 X 向前、Y 向左、Z 向上，允许负数；速度为三维路径的合速度 |
| 悬停指定时间 | 秒；停止平移和转向，保持悬停 |
| 停止移动并悬停 | 不关闭电机，不等于紧急停机 |

- 对应本地 cflib `MotionCommander.take_off/land/move_distance/turn_left/turn_right/circle_left/circle_right/stop`。不使用 `HighLevelCommander.stop`，后者会关闭电机。
- 运动需可用的定位能力（例如 Flow deck），仿真不替代实际定位质量、净空和电量检查。使用顺序：起飞 → 运动 → 降落；真机流程未连接时自动连接，已连接则复用。新运动流程会在发送前检查起飞顺序、重复起飞和无效参数；仍必须显式使用起飞积木，不会因为连接而自动起飞。旧飞行积木仍保留。
- 执行器不再因进入 MotionCommander 上下文而提前起飞，而是执行到起飞积木才起飞；结束或异常退出时仍调用降落清理。旧的无参数起飞使用 cflib 默认 0.3 米，旧直线运动默认速度为 0.2 米/秒，仿真采用相同高度与速度，并以停机面为高度基准。
- 仿真按照当前航向计算前后左右和三轴位移，并展示转向、圆弧和高度变化。IPC 超时会在原有一分钟余量上计入新运动、悬停、等待与参数化降落的预计时间，避免正常长动作仍按固定一分钟被终止。
- 本批不新增遥测/实时传感器条件、参数写入、定位校准、固件升级或底层姿态/推力积木。新运动不能放进旧式实时测距分支；基础条件与循环仍按前述运行前展开规则执行。
- 回归测试覆盖全部运动 API 的模拟调用、完整 Python 执行器的无硬件连接替身、降落清理、三维轨迹、速度与取消。尚未在真实飞行器上验证新增运动。

### 自动显示真实姿态

- 点击页头连接后，默认持续读取 `stabilizer.roll/pitch/yaw`，不需要运行积木或另外打开开关。移除重复的“只读姿态”开关与独立 URI 设置，统一使用页头选定的无线收发器及工程连接参数。
- 真机横滚、俯仰、偏航数值放在三维画面左上角的位置读数下方，跟随设置语言显示，未连接时为 `--°`，过期或异常时保留末次值并标黄；这些数值仍来自真机，不会替换为模拟姿态。右上角仅保留紧凑的姿态模型、状态和主场景标准视角选择，宽度随面板在 96～120 像素间调整，减少遮挡主地图。左侧读数为右侧小窗预留空间，窄面板自动换行而不重叠。模型上的机体坐标随实测姿态一起旋转：红色 X 朝前、绿色 Y 朝左、蓝色 Z 朝上，与主场景坐标使用同一映射，正确扣除模型自身的朝向偏移。切换主视角不会改变真机姿态；姿态预览不表示真实位置或飞行轨迹，也不显示虚构的电机转速。
- 小窗复用主场景的 WebGL 渲染器，以独立相机和裁剪视口绘制，不创建第二个渲染循环或第二条无线连接。缩放、旋转教室视角或切换场景不改变小窗观察方向。模型资源与主场景共享，替换官方模型、螺旋桨或扩展模块后同步更新。
- 空闲连接时，场景中的飞机也默认跟随真实姿态，但位置仍为模拟位置；运行“仅模拟”时，主场景按模拟航向运行，小窗仍独立显示实物姿态。“模拟+真机”继续使用包含 XYZ/RPY 的同包数据更新相对起点的位置、姿态与轨迹；自动读取的空闲 RPY 包不会被误当作位置数据。
- 姿态、页头连接和实飞流程共用一个持久连接。空闲时不发送解锁、电机或飞行指令；执行前停止空闲姿态日志，运行时共享流程日志，结束或普通流程出错后恢复空闲姿态日志。日志切换可短暂等待新样本，不重新连接。姿态日志故障会显示异常，不因此中断普通实飞；同步飞行仍要求有效的位置与姿态。
- 关闭三维面板只释放显示资源，不停止连接上的自动姿态采集；重开即可使用缓存与新样本。断开或更换飞行器时清空旧姿态，晚到的数据不能恢复已断开的状态。其他窗口不能同时占用该连接；外部 cfclient 等客户端须自行关闭。
- 目标采样周期为 50 ms（20 Hz），显示使用四元数和平滑插值，避免航向跨越 ±180° 时整圈翻转。超过 500 ms 无新样本标记过期并保持末次实测值；姿态日志超过 1 秒无新数据会明确报错，可断开后重连。电池链路监测独立保持，不用陈旧姿态冒充实时值。
- 接收数据年龄不是无线端到端延迟。无硬件测试覆盖自动订阅、日志切换和清理、连接复用、空闲/运行数据区分、姿态映射、独立小窗、主视口状态恢复、数据过期及断线清理；未验证真机无线延迟或实际飞行表现。
- 回归命令：`node --test scripts\test-crazyflie-preview.cjs scripts\test-crazyflie-connection.cjs scripts\test-crazyflie-attitude.cjs scripts\test-crazyflie-basic-blocks.cjs scripts\test-crazyflie-sync.cjs scripts\test-electron-logger.cjs`。

### 持久连接与多个无线收发器

- 页头连接图标左边缘与积木分类栏右边缘对齐，拖动分类栏宽度后同步更新。无线收发器下拉框显示简洁的“Crazyradio 1 / 2 …”（对应 USB 枚举编号加 1），完整 USB 序列号只放在悬停提示中；实际选择和连接仍按序列号匹配。只有一个设备时自动选择；多个设备时必须主动选择，或在无线参数积木中明确配置编号，不能悄悄使用编号 0。
- 运行模式与“运行”整体放在无线收发器右侧，使用 14 像素文字及图标；窄窗口下模式切换显示图标并保留名称提示。三维显隐按钮放在右侧工具区、“查看代码”左边。Crazyflie 工程名称在底部状态栏居中显示，窄窗口为两侧操作与遥测保留空间，长名称省略显示、悬停可查看完整名称；其他开发板的页头布局保持原有行为。
- Crazyflie 编辑器未连接时自动读取设备列表，每次读取结束后等待 2 秒再检查，支持软件启动后插入、拔出和重新插入无线收发器。按序列号保留仍在线的选择，USB 编号改变不会误选；未连接且只剩一个设备时自动选择，但不会自动连接或启动电机。聚焦下拉框也可立即刷新，并发刷新合并为一次读取。连接、执行期间暂停自动枚举，避免干扰无线链路；断开后自动恢复。检测失败会提示并保留错误说明，重试成功后清除。
- 点击连接会真正打开并保持所选设备到飞行器的链路，等收到有效电池遥测后才显示已连接。提示显示“无线收发器编号 · 序列号 → 完整飞行器 URI”。底部持续更新电压、估算电量和无线链路质量；Link、Battery 的百分比预留完整 `100%` 的宽度，电压另用固定宽度与等宽数字显示，数值变化不会挤动进度条。电量百分比不是精确剩余容量，链路质量也不是距离或 RSSI。未知或过期的质量显示 `--`，不是 0。
- 物理设备通过 `cflib.drivers.crazyradio.get_serials()` 枚举。建立连接后使用带 USB 序列号的 URI，避免 USB 插拔导致编号变化时误选另一设备。当前一次只控制一架飞行器，不提供多机编队。
- “连接”积木在未连接时自动连接，已连接同一目标则直接复用，不会再建立第二条链路；也可以不放连接积木，直接执行起飞、运动和降落流程。页头和积木使用同一套无线参数，已连接后参数不一致会在发送运动前明确拒绝；换设备、信道或飞行器地址前须先断开。
- 飞行期间不能断开、切换无线收发器或重复运行。取消和执行超时会通知当前执行器并等待动作及降落清理结束，不强杀可能还在飞行的进程，不自动重放失败计划。空闲时可点同一图标真正断开；页面离开或窗口关闭也会清理连接。关闭三维面板不停止自动姿态采集，也不断开页头连接。
- 无效电池数据、日志故障、超过 3 秒没有新电池数据或掉线都会明确报错，清除遥测并停止本会话。扫描必须在连接前进行，已连接时需先断开，不能另开无线驱动争用同一设备。仅模拟不会自动连接实物。
- Windows 后台在启动控制输入线程前完成 cflib/NumPy 原生运行库初始化，避免控制管道阻塞读取与原生库加载死锁，导致检测停在 0% 或页头连接超时。USB 枚举不启动控制线程，也不代表已经连接飞行器。
- 连接复用、设备选择、遥测和取消行为已用离线替身验证；真实 USB、无线链路和飞行效果仍需在安全场地使用实物验证。

- 切换后等待语言加载和当前工程保存完成，再重新加载积木定义，保留积木连接、参数和生成代码；保存失败会明确提示，不重新打开工程。

### 基础示例

三维面板的“基础示例”按钮使用醒目的主题文字；下拉列表以分隔线、独立间距及悬停高亮区分各项，标题加粗、说明使用较弱文字色。列表超过屏幕可用纵向滚动条，最大高度随视口缩小。以下积木流程每次在新页面中创建，不覆盖原页面，不自动运行，也不更改当前运行模式：

- **基础自检（不飞行）**：检测无线收发器 → 等待 2 秒 → 连接 → 等待 2 秒 → 自检（真机等待固件完成反馈）→ 等待 3 秒。最后 3 秒是自检结束后的观察时间，不用于猜测自检耗时。不包含起飞、移动或降落；真机自检会驱动电机，必须先拆下螺旋桨。
- **起飞、悬停、降落**：连接后等待 2 秒，起飞 0.3 米，等待悬停 3 秒，降落后等待 2 秒。
- **前后移动**：连接及起飞后各等待 2 秒，以 0.2 米/秒前后各移动 0.3 米，动作间等待 1 秒，降落后等待 2 秒。
- **方形航线**：连接及起飞后各等待 2 秒，以 0.2 米/秒向前、左、后、右各移动 0.3 米，动作间等待 1 秒，降落后等待 2 秒。
- **LED 灯环：三色切换**：连接 → 等待 2 秒 → 检测 LED 灯环 → 等待 1 秒 → 红、绿、蓝各亮 1 秒 → 关闭灯环。RGB 通道亮度为 64。
- **LED 灯环：循环闪烁**：连接及检测灯环后，使用基础重复积木让蓝灯亮 0.5 秒、灭 0.5 秒，共 3 次，以熄灯结束。
- **蜂鸣器：悦耳提示音**：连接及检测蜂鸣器后，播放官方固件的启动提示（`sound.effect=6`，最长 1500 毫秒），间隔 0.5 秒，再播放完成提示（`sound.effect=4`，最长 800 毫秒），最后等待 1 秒。到时或取消时将效果设为 0；不再用工厂测试音拼接节奏。需要安装蜂鸣器并使用支持 `sound.effect` 的固件，参考 [官方蜂鸣器教程](https://www.bitcraze.io/documentation/tutorials/getting-started-with-buzzer-deck/)。
- **摄像头：手势事件**：在新页面添加摄像头配置、打开画面、开启识别的启动链，以及两个独立手势事件。张开手掌或握拳保持 1.2 秒后只打印提示，不起飞、不自动授权或更改模式。先修改设备 IP，以模拟模式验证，再将事件中的打印积木替换为自己的动作。保持同一手势只触发一次，放下手后才能重复触发。
- **摄像头①：获取图像**：仅配置摄像头 IP 并打开画面，在积木内预览视频；不启动识别、不连接无线或控制飞行。视频可移动和缩放，关闭后停止串流。
- **摄像头③：手势起飞与降落**：启动摄像头及识别后，张手保持 1.2 秒触发起飞 0.3 米、悬停 10 秒、降落；握拳保持 1.2 秒可提前请求降落。飞行动作仍由事件下的积木定义，并非识别器内置映射。先试模拟；真机先连接、完成定位检查，运行后再手动勾选摄像头授权。关闭识别或画面会取消动作并请求降落，但失联或硬件故障时不能保证落地，仍需独立的安全停机措施。
- **测距避障：五向距离观察**：连接及检测 Multiranger 模块后，用基础重复积木打印前、后、左、右、上方距离，共 5 轮，每轮后等待 1 秒。距离在执行读取指令时获取，不是运行前固定数值；本示例不起飞，也不根据距离自动移动或避障。

示例插入前会校验所需积木，运行中不能新建示例。请先选择“仅模拟”验证；真机飞行前检查定位条件及场地。等待时间用于分隔步骤、观察状态，不保证硬件已就绪或替代真实运行时检查。

LED 灯环分类新增 **设置灯环颜色〔颜色〕**，提供红、绿、青、蓝、紫、黄、橙、粉、白九种预设；生成已有 RGB 指令，旧积木和旧工程保持兼容。原红绿蓝数值积木保留，可用于自定义亮度。蜂鸣器分类新增 **播放〔提示音〕最长〔毫秒〕**，提供启动、完成、校准、USB 接入/拔出五种官方固件提示音；时长为 100～5000 毫秒，播放或停止失败会明确报错，不伪装成功。

手势事件积木显示随下拉选择更新的本地 SVG 示意图，保存、撤销和重新打开工程时同步恢复。原七种手势保留，新增 **OK** 及 **手掌向左、右、上、下滑动**，共 12 种。OK 使用本地手部关键点判断拇指与食指捏合、其余三指伸直；食指指向允许手部旋转，保留原 `Pointing_Up` 保存标识。新增规则不是重新训练的分类模型，效果取决于手部完整可见、光照和摄像头清晰度。

滑动事件的秒数是**先张开手掌静止保持的准备时间**，不是移动后继续保持的时间。准备完成后在约 1 秒内，沿视频画面方向移动至少一掌宽（且不小于画面宽/高的 12%），连续两帧确认后触发一次；再次触发前放下手至少 0.5 秒。斜向、手部尺寸明显变化、缺帧或多人画面不触发滑动。摄像头应固定，方向不等于飞行器坐标；识别器只输出事件和时间，不内置任何飞行动作。

四个扩展示例不包含起飞、自检或其他电机指令。真机执行需要安装对应扩展板；仅模拟时，灯环和蜂鸣器动作只显示日志，不会播放声音或证明真机扩展板已就绪。模拟测距只参考当前场景的外边界，不包含家具碰撞。当前基础条件无法使用实时测距读数，因此“五向距离观察”是避障入门的读数练习，不是自动避障程序。

### 测距建图（不依赖 ROS2）

在“坐标系”场景点击画布下方“复位”右侧的 **建图**，可用已有位姿与五向测距累积三维障碍点云，按 10 cm 体素去重。支持模拟采集、真机只读采集、暂停、清空和 JSON 导出。控制区独立于画布和姿态 HUD，长说明默认折叠，不覆盖地图。地图按当前三维坐标参考系显示，导出使用米制 **X 前、Y 左、Z 上**，记录数据源、位姿参考点和体素命中次数。

建图默认显示 **二维栅格**，可切换 **三维点云**；切换只改变显示，不重启采集、不丢弃地图或改变飞行。二维图中，**黑色是已测到的障碍/墙体，浅色是有效测距射线经过的已观测空闲区域，灰色是未知区域**。只描绘实际观测，不自动补齐墙体、封闭轮廓或把未知区域填成空闲。可拖动平移、滚轮缩放，也可用顶部放大/缩小、适配、聚焦及截图按钮；三维旋转、三维测距工具和轨迹在二维模式暂不可用。关闭建图控制区会回到原三维场景。

二维栅格同样为 10 cm，只使用前后左右中相对水平面倾角不超过 10° 的有效射线，不把上方测距直接当作平面墙体。障碍终点标为黑色，终点之前的射线栅格标为浅色；无效和超量程读数目前同为缺失数据，**不会清空到最大量程**。不同高度的观测投影到同一个平面，已观测障碍保留至清空地图，后续空闲射线不会抹去它。浅色仅表示传感器高度上曾观测到空闲，不保证整列空间、飞行器尺寸或动态场地安全；此功能不是自主导航或飞行许可。

可在飞行中开始采集。每帧按当时的 XYZ 与横滚、俯仰、偏航将机体方向测距投影到同一个世界坐标系；飞行器移动或转向只新增观测，不会转动旧地图。若从地面开始采集，随后起飞重置了估计器，则按提示清空旧地图，再在稳定定位后采集；不会为了连续显示而忽略参考点变化。

- **先试模拟**：选择“模拟采集”，灰色线框显示专用的约 4×4 m 测试围墙、顶面和箱体，绿色点为对这些障碍进行射线测距的结果，不是实测地图。随后仅在“仅模拟”模式运行移动、转向积木可逐步补充轮廓。开始采集本身不运行积木、不自动起飞，也不改变运行模式；测试障碍不参与飞行碰撞保护，不会把坐标网格边界当成真实墙面。
- **真机采集**：先通过现有入口连接真机，安装 Multiranger 并提供可靠定位（例如合适的光流、Lighthouse 或外部定位）。点击“真机采集”只复用已有无线连接读取位置、姿态和距离，不设置估计器、不解锁、不控制电机。橙色点为真机测距结果；移动仍由用户另行控制。模拟数据与真机数据不能混入同一张地图，切换前需清空。
- **采样与保护**：仅在开启时注册两组 5 Hz 日志：六个 XYZ/RPY 浮点数为 24 字节，五个毫米测距值为 10 字节，分别符合 CRTP 单包 26 字节上限。使用飞控的 24 位时间戳配对，最多允许 50 ms 差，支持时间戳回绕；超过 1.5 秒无有效配对、断线、日志错误或定位参考点重置会暂停入图并提示。0、无效或达到 4 m 上限的读数不会生成障碍点。暂停会停止这两组日志，不影响正在运行的飞行流程；参考点重置后保留旧地图供导出，但必须清空才能重新采集。
- **资源边界**：最多 20000 个三维体素及 20000 个二维栅格，坐标范围为各轴 ±50 m；达到任一限制会明确暂停，当前帧不部分写入，也不悄悄丢弃旧点。切换场景或关闭面板会结束采集；关闭面板不影响飞行，内存地图随面板销毁，需提前导出保存。
- **导出**：保留原三维 JSON 字段，新增 `occupancy` 稀疏二维栅格，使用米制 X 前、Y 左的格心坐标，`100` 为障碍、`0` 为已观测空闲；未列出的栅格为 `-1` 未知。包含分辨率、观测次数和投影限制，不把未观测区域导出为空闲。

**这不是 SLAM、稠密重建或自动避障。** 当前不做回环、定位漂移校正、占据概率或多机地图配准；五束测距只能记录稀疏反射点，缺少下方观测，未显示点的位置不能视为可通行空间。点云只是实验观测，不应作为飞行安全依据。真机测距、姿态与定位精度仍需在安全环境中验证。

思路参考：[Crazyflie 测距建图教程](https://bitdeck-docs.readthedocs.io/zh-cn/latest/bitcraze/crazyflie/crazyflie_firmware_develop/1_crazyflie_firmware_ros2_gazebo.html) 和 [多机器人地图合并示例](https://github.com/abdulkadrtr/mapMergeForMultiRobotMapping-ROS2)。已检查本地参考实现：它按已知地图原点和分辨率拼接二维占据栅格，不包含位姿估计或自动配准，不能直接解决动态三维测距。这里只借鉴统一坐标和增量更新，没有引入 ROS2/Gazebo 依赖，也未实现多机地图合并。

回归测试：`node --test --test-concurrency=1 scripts/test-crazyflie-mapping.cjs scripts/test-crazyflie-occupancy-view.cjs scripts/test-crazyflie-connection.cjs scripts/test-crazyflie-attitude.cjs`，不连接硬件。

### 摄像头

点击左侧 **蜂鸣器** 下方的 **摄像头**，将 **打开画面** 积木拖入工作区，预览窗口就在这个积木下方，随积木拖动、工作区平移和缩放，不占用右侧二维/三维地图区域。预览的 `+ / −` 按钮可单独放大或缩小窗口（宽度 240～640 工作区像素），宽度随工程保存，撤销/重做也可恢复；复制、加载工程和点击分类不会自动联网。分类、窗口和积木使用“摄像头”名称，内部标识保持兼容已有工程。

可在积木内输入设备 IP（可带端口）或完整 HTTP(S) 视频流地址，点击“打开”，不需要运行飞行程序；地址尚未填写时可读取同一积木链前面的文字型“配置地址”。变量地址须先运行配置积木或手动输入。点击“关闭”或 `×` 隐藏视频并结束请求，保留积木和打开按钮；程序中的打开/关闭积木也控制同一预览。多个打开积木共用一条视频连接：手动打开哪个就显示在哪个下方，程序按实际执行的积木显示，新窗口打开会关闭旧画面。删除正在预览的积木、切换工作区页面或离开编辑器会结束请求。关闭三维模拟器后仍可使用。仅输入 IP 时使用 `http://IP/stream`；完整地址保留自定义路径。电脑需能访问 Deck 所在网络，ESP32-S3 使用 2.4 GHz Wi-Fi。不要求 Crazyradio 或飞行器连接，点击分类本身不连接视频、不运行程序或控制电机。

提供三个电脑端积木：**配置地址 → 打开画面 → 关闭画面**。例如连接“配置地址 192.168.4.1 → 打开画面 → 等待 5 秒 → 关闭画面”，运行时按顺序执行；地址支持文字和变量，支持有界循环，并随工程中的积木保存。每个要打开画面的程序都必须先配置有效地址，错误地址或缺少配置会在执行前报错。“打开画面”发起请求，不会等待首帧才继续下一条积木，需要观察时添加等待。流程结束或取消不会擅自关闭已打开的视频，可用关闭积木、预览中的关闭按钮或 `×` 结束请求。

三种运行模式都直接访问真实摄像头地址，不伪造模拟视频。仅包含摄像头、等待和输出的程序在本机执行，不需要 Crazyradio、Python 或 cflib，也不复位三维模型。混合真机程序由现有单次飞行任务按序发出摄像头事件，不拆开飞行连接或重复起飞；视频失败在面板报错，不代表飞行已取消，不能将视频连通性当作飞行安全或视觉定位保证。

接口已对照 [esp32s3_ai_deck](https://github.com/bitdeckai/esp32s3_ai_deck) 的 `esp32s3_ai_deck_allinone/main/main.c`：默认 HTTP 端口提供 `/stream` MJPEG，首页也通过这个接口显示画面。这里直接显示视频，不嵌入远程网页，不读取图像像素，因此不要求固件添加 CORS；不另开 `/fps` 请求占用设备 HTTP 服务。首帧须实际解码才显示“画面已打开”，8 秒无画面或网络失败明确报错，关闭或销毁预览会结束视频请求。重新加载积木保留本次应用会话的地址，但不会自动重连；手动地址不写入工程或云端，配置积木的地址则属于工程内容。

固件已初始化摄像头，无需照抄 ESP32 开发板的摄像头型号、引脚或烧录积木；当前接口也没有画质/引脚配置 API，不显示无法生效的设置。支持自定义端口/路径用于其他兼容 MJPEG 固件。回归：`node --test --test-concurrency=1 scripts/test-ai-deck-camera.cjs scripts/test-crazyflie-basic-blocks.cjs scripts/test-crazyflie-sync.cjs`，视频仍需用实际设备验证网络和帧率。

### 手势事件积木

摄像头分类还提供 **开启手势识别**、**停止手势识别** 和 **当识别到〔手势〕保持〔秒数〕→ 执行**。识别模块只报告手势和保持时间，不固定映射起飞、降落或其他动作。把飞行、蜂鸣器、LED、输出等积木接在事件的“执行”区域即可。支持张开手掌、握拳、食指向上、拇指向上/下、胜利及我爱你手势。每种手势定义一个事件，可在同一事件内连接多个动作；不要把事件放进循环或把普通动作混放到识别启动链中。

启动链可用“配置地址 → 打开画面 → 开启手势识别”。点击“运行”会注册工程中的事件，启动链结束后保持识别。也可先在预览内手动开启识别，只查看识别结果，未运行注册事件时不执行动作。拖拽、加载或复制事件积木本身不会联网或操作设备。事件内的基础条件、变量及有界循环沿用现有展开规则，在本次运行时解析并保存快照，修改积木后需要重新运行注册。

识别使用电脑本地的 MediaPipe Gesture Recognizer，模型及 WASM 随应用提供，不下载云端模型或上传画面。桌面应用通过有随机地址、只监听本机的只读视频转接读取像素，不要求 ESP32 固件增加 CORS，不关闭浏览器安全检查，不产生第二条设备视频流。首次使用新接口需要重启桌面应用。识别只接受单只手及至少 0.85 的置信度；保持时间为 0.5～5 秒，真机事件至少确认 1.2 秒。同一手势保持只触发一次，放下手至少 0.5 秒后才能再次触发；另一种稳定手势可产生新的事件。多人、多手、无效画面及低置信度不触发动作。

模拟事件保留模型当前位姿；真机事件需要先手动连接并确认可飞状态，再勾选预览中的授权。更换模式、连接、页面或关闭/停止识别都会撤销授权。动作复用原有单次执行流程及其超时、取消和降落收尾；识别不是安全或适航保证。**真机飞行事件的动作子程序结束时仍执行现有的降落收尾**，需要悬停观察请在该事件内放等待/悬停积木。另一事件仅包含降落积木时，可请求取消当前由手势启动的飞行，并等待其降落收尾；不会取消其他普通程序。其他并发事件明确报忙，不缓存后续起飞。视频中断、过期、停止识别或应用隐藏时停止触发，并请求取消本次手势动作；这不是紧急停机，仍需观察真机状态。

当前是手势事件识别，不提供视觉定位、避障或视频建图。真实手势精度、设备延迟和真机动作需在安全环境下进一步验证。
